# Stock Alerts Application

## Overview
A stock alert system that monitors S&P 500 stocks and sends Slack notifications based on configurable rules. Uses an independent rule agents architecture where each alert rule runs as a separate Lambda function.

## Architecture

### Frontend
- **App URL:** https://main.djiqwmbk5ujjm.amplifyapp.com/
- `index.html` - Configuration UI hosted on AWS Amplify
- Single-page app with toggle switches, threshold inputs, and individual test buttons for 6 alert rules

### Backend (AWS Lambda)

#### Lambda Layer
- `lambda/layers/stock-utils/` - Shared utilities layer
  - `data-fetcher.js` - Yahoo Finance API integration
  - `slack-notifier.js` - Slack message formatting and sending
  - `stock-list.js` - S&P 500 stock symbols (~450 stocks)

#### Rule Functions (Independent Agents)
Each rule runs as an independent Lambda function that can be triggered separately:
- `lambda/rules/rule1-daily-drop.js` → `stock-alert-rule1`
- `lambda/rules/rule2-two-day-drop.js` → `stock-alert-rule2`
- `lambda/rules/rule3-recovery-signal.js` → `stock-alert-rule3`
- `lambda/rules/rule4-near-52w-low.js` → `stock-alert-rule4`
- `lambda/rules/rule5-bounce-back.js` → `stock-alert-rule5`
- `lambda/rules/rule6-volume-surge.js` → `stock-alert-rule6`

#### Orchestrator
- `lambda/orchestrator.js` → `stock-alert-orchestrator`
- Triggers all enabled rules on daily schedule (10 AM EST weekdays)
- Invokes rule functions asynchronously in parallel

#### Config API
- `lambda/config-api.js` → `stock-alerts-config-api`
- REST API for configuration and triggering rules
- Endpoints:
  - `GET /config` - Get current configuration
  - `POST /config` - Update configuration
  - `POST /run` - Run all rules via orchestrator
  - `POST /rule/{ruleId}/run` - Run individual rule (NEW)

### AWS Resources
- **Lambda Functions:**
  - `stock-alert-rule1` through `stock-alert-rule6` - Individual rule processors (180s timeout, 256MB)
  - `stock-alert-orchestrator` - Daily scheduler (30s timeout, 128MB)
  - `stock-alerts-config-api` - Configuration API (90s timeout, 256MB)
- **Lambda Layer:**
  - `stock-utils` - Shared utilities
- **API Gateway:** HttpApi for Config API endpoints
- **EventBridge:** Schedule rule for weekday 10 AM EST runs (triggers orchestrator)
- **IAM Roles:** Auto-generated by SAM for each function with appropriate permissions

## Alert Rules

### Downside Alerts
1. **1-Day Drop** - Stock dropped >X% today
2. **2-Day Drop** - Stock dropped >X% over 2 days

### Upside Potential Alerts
3. **Recovery Signal** - Dropped >X% in 5 days but UP >Y% today
4. **Near 52-Week Low** - Within X% of 52-week low
5. **Bounce Back** - Dropped >X% yesterday but up >Y% today
6. **High Volume Surge** - Up >X% with volume >Y times average

## Data Source
- Yahoo Finance API (fetched live on each run)
- ~450 stocks monitored (S&P 500 + popular growth stocks)
- Batch processing: 15 stocks per batch, 500ms delay between batches

## Slack Integration
- Webhook: Configured in Lambda environment variable `SLACK_WEBHOOK_URL`
- Channel: #stock-alerts
- Single-rule alerts: Dedicated message per rule
- Multi-rule alerts: Combined message from orchestrator

## Deployment

### Using SAM (Recommended)
```bash

# Build the application
sam build

# Validate template

# Deploy (first time - interactive)

# Deploy (subsequent times)
sam deploy

# Deploy with specific parameters

```

### Manual Testing
```bash
# Test orchestrator (runs all enabled rules)
aws lambda invoke --function-name stock-alert-orchestrator \
  --payload '{}' response.json

# Test individual rule
aws lambda invoke --function-name stock-alert-rule1 \
  --payload '{"forceRun": true}' response.json

# Test rule via API
curl -X POST https://YOUR_API_URL/rule/1/run

# Monitor logs
aws logs tail /aws/lambda/stock-alert-rule1 --follow
```

## Triggering Rules

### Via API


### Via CLI
```bash

  --payload '{"forceRun": true}' response.json
```

## Configuration

Each rule has its own environment variables:
- `RULE{N}_ENABLED` - Enable/disable rule ('true'/'false')
- `RULE{N}_THRESHOLD` - Primary threshold value
- `RULE{N}_THRESHOLD1` - First threshold (for multi-threshold rules)
- `RULE{N}_THRESHOLD2` - Second threshold (for multi-threshold rules)
- `SLACK_WEBHOOK_URL` - Slack webhook URL (same for all rules)

Configuration can be updated via:
1. Frontend UI (recommended)
2. Config API POST /config endpoint
3. AWS Console (Lambda function environment variables)

## Benefits of Independent Rule Architecture

1. **Independent Triggering** - Each rule can be tested/run separately
2. **Better Observability** - Separate CloudWatch logs per rule
3. **Easier Debugging** - Isolate issues to specific rules
4. **Parallel Execution** - All 6 rules run simultaneously (faster)
5. **Modular Code** - Easy to add/modify rules without affecting others
6. **Flexible Scheduling** - Can add different schedules per rule in future
